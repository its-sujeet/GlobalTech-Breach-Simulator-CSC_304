CSC401: Database Log Analysis

Security Audit Report

Presented by: Sujeet Kumar

Roll No: 16 | Section: 423CS

Reg Number: 12303890

The Mission

"Unauthorized database queries have been detected. You must analyze database logs to identify suspicious access and potential data breaches."

  • Analyze 1500+ database access logs.
  • Identify suspicious access patterns.
  • Report on potential data breaches.

The Method

We built a Python-based Log Analyzer that scans for:

  • External Access: IPs outside the trusted range.
  • SQL Injection Signatures: UNION, OR '1'='1', SLEEP().
  • Access Control Violations: Guests accessing sensitive tables.
  • Privilege Escalation: Unauthorized UPDATE queries.

Findings Overview

6 Critical Security Events Identified

All attacks originated from the same external IP: 203.0.113.5

  • UNION SQL Injection (Data Exfiltration)
  • Auth Bypass SQLi (Login Bypass)
  • Blind SQL Injection (Reconnaissance)
  • Privilege Escalation (Role modification)
  • Unauthorized Access (Financial records probed)
  • Mass Data Deletion (Orders table cleared)

↓ Scroll down for deep dives on each attack ↓

Deep Dive 1: Data Exfiltration

The attacker used a UNION operation to steal user credentials.


SELECT * FROM products WHERE id = 42 
UNION 
SELECT username, password, email, role FROM users --;

Analysis:

  • The attacker combined product results with user data.
  • The double dash -- comments out the rest of the query.
  • Result: Passwords and emails leaked in search results.

Deep Dive 2: Auth Bypass

The attacker bypassed the login screen using a tautology.


SELECT * FROM users 
WHERE username = 'admin' OR '1'='1' 
AND password = '';

Analysis:

  • The condition '1'='1' is always true.
  • This forces the database to return the admin record regardless of the password.
  • Result: Attacker gains full administrative access.

Deep Dive 3: Privilege Escalation

Attempt to grant admin rights to a web user account.


UPDATE users 
SET role = 'admin' 
WHERE username = 'web_app_user';

Analysis:

  • This query was executed by `web_app_user` itself.
  • Normal users should not have permission to run UPDATE on the users table.
  • Result: Escalation of privileges if not blocked.

Deep Dive 4: Blind SQLi

The attacker used the SLEEP function to infer vulnerability.


SELECT * FROM products WHERE id = 1 
AND (SELECT 1 FROM (SELECT(SLEEP(5)))x);

Analysis:

  • The SLEEP(5) function pauses the database for 5 seconds.
  • By measuring the response time, the attacker confirms the injection point works.
  • Result: Confirms vulnerability for further extraction.

Deep Dive 5: Unauthorized Access

A guest user attempting to read sensitive tables.


SELECT * FROM financial_records;

Analysis:

  • The log shows `guest_user` executing this query.
  • Guest accounts should not have access to the `financial_records` table.
  • Result: Access was denied, but it shows malicious intent.

Deep Dive 6: Mass Deletion

Unauthorized deletion of the entire orders table.


DELETE FROM orders;

Analysis:

  • Executed by `reporting_service`.
  • A reporting service should only have read access, never delete permissions.
  • Result: Potential total loss of order history data.

Remediation

  • 1. Parameterized Queries: Stop SQL injection by separating code from data.
  • 2. Least Privilege: Restrict service accounts to minimum required access.
  • 3. Network Controls: Block IP 203.0.113.5 at the firewall.
  • 4. Real-time Monitoring: Deploy automated log analysis.

Conclusion

  • Logs are the black box of security.
  • Proactive analysis can stop breaches before they spread.
  • Always monitor for anomalous access!
