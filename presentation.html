Roll No: 16 | Section: 423CS

Reg Number: 12303890

Project Objective

  • Investigate a suspect database-backed web application.
  • Identify SQL Injection (SQLi) vulnerabilities.
  • Extract sample sensitive data to demonstrate business impact.

The Target Application

GlobalTech Corporate Portal

  • A custom Node.js/Express web application.
  • Uses an in-memory SQLite database.
  • Contains a built-in "Researcher Toolbox" for real-time query visualization.

Vulnerability Discovery

We identified 5 critical SQL Injection endpoints:

  • /api/login (Authentication Bypass)
  • /api/search (Data Exfiltration / UNION)
  • /api/profile/update (Privilege Escalation)
  • /api/register (Unrestricted Account Creation)
  • /api/blind-check (Blind Inference)

↓ Scroll down for more details on specific attacks ↓

Auth Bypass Detail

Endpoint: /api/login


const query = `SELECT * FROM users 
               WHERE username = '${username}' AND password = '${password}'`;

By injecting ' OR 1=1 -- in the username, the query becomes always true, bypassing authentication.

Privilege Escalation Detail

Endpoint: /api/profile/update


const query = `UPDATE users SET username = '${displayName}', email = '${email}' 
               WHERE username = '${username}'`;

An attacker can inject hacker', role='admin into the display name to elevate their privileges.

The Attack: Data Exfiltration

Target: /api/search


// The Vulnerable Code
const query = `SELECT id, username, role, email FROM users 
               WHERE username LIKE '%${searchTerm}%'`;

The Exploit Payload:


x' UNION SELECT id, user_id, secret_data, 'EXFILTRATED' 
   FROM secret_vault --

Remediation

To prevent SQL Injection, the application must use Parameterized Queries.


// Secure Implementation
const query = `SELECT * FROM users WHERE username = ? AND password = ?`;
db.get(query, [username, password], (err, row) => { ... });

* This fix has been implemented and can be activated via the "Parameterized Shield" toggle in the lab.

Conclusion

  • SQL Injection remains a critical threat.
  • Unsanitized input can lead to total database compromise.
  • Always use Parameterized Queries!
