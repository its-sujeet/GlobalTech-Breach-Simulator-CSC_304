CSC306

Android Reverse Engineering & Code Analysis

Auditor: Sujeet Kumar (Roll No: 16)

Objective

To understand application logic and identify security vulnerabilities in an Android APK file using reverse engineering techniques.

The Process

  1. Source Code: Written with intentional vulnerabilities.
  2. Build: Compiled into an APK (Dalvik Executable).
  3. Decompile: Used JADX to recover Java source from the APK.

Finding 1: Hardcoded API Key

A sensitive Google API key was found stored in plain text in the source code.


// Found in MainActivity.java
private static final String API_KEY = "AIzaSyD-7Xj2J8K9L0M1N2O3P4Q5R6S7T8U9V0";

Risk & Remediation

Risk: High. Attackers can steal the key and abuse the API quota.

Remediation: Move keys to a secure backend or use Android Keystore.

Finding 2: Active Debug Flag

The app was compiled with the debug flag set to true, enabling verbose logging.


// Found in MainActivity.java
private static final boolean DEBUG_MODE = true;

if (DEBUG_MODE) {
    Log.d("DEBUG_LOG", "Initializing with API Key: " + API_KEY);
}

Risk & Remediation

Risk: Medium. Exposes sensitive data in system logs (logcat).

Remediation: Disable debugging in production builds using ProGuard/R8.

Finding 3: Hidden Endpoint

A hidden administrative endpoint was discovered in the decompiled code.


// Found in MainActivity.java
private static final String HIDDEN_ADMIN_ENDPOINT = 
    "https://api.vulnerableapp.com/v1/internal/debug/grant_admin_access";

Risk & Remediation

Risk: Critical. Allows unauthorized access to admin functions.

Remediation: Remove debug endpoints from production code completely.

Conclusion

Reverse engineering is a powerful technique to audit app security.

Obfuscation and proper secret management are essential to protect Android applications.
